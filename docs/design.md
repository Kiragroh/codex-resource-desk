# Resource Desk — design, 13 October 2026

Portable native Windows x64 companion for Codex. English UI; dark graphite, UKL blue #008AC9 and purple #8064A2 accents, clear hierarchy and compact visual resource attribution. User approved native portable resource view with system/Codex totals, hover details, simple enable/disable switches and retained disabled integrations. Unity must stay enabled for the user's first interactive test. Hostinger is already disabled and must stay that way until the user changes it.

System card: total/used/available physical RAM. Codex card: private resident RAM of attributed Codex processes, separately labelled private committed memory. Process card: attributed process count and active integrations. A clickable stacked bar and per-row relative bars connect totals to integrations. Hover reveals definitions and counts; selecting a row shows PID, executable, age and memory. Search and All/Running/Disabled filters. Deactivated components remain listed with zero live processes.

Controls operate on global local mcp_servers tables in the selected Codex config, including the nine Hostinger servers as one family. Off offers Disable only or Disable & stop attributed processes; enabling changes config but never executes stored commands. Explain reload semantics. Built-in Codex and browser helpers are visible/read-only. Ambiguous attribution is read-only. Stop validates PID/start-time and ancestry; no kill-all Node action. User settings and raw process commands never enter public exports.

Native .NET 10 WPF application, self-contained portable folder and ZIP. CPU-only monitoring, no Electron/Node runtime, no network service, no autostart, no admin elevation. Background sampling every five seconds, single in-flight refresh. WMI command-line inventory with cached stable process identities; native Windows memory sampling. Private working set is used to avoid double-counting shared resident pages; committed memory is separately labelled.

Configuration edits preserve original bytes except enabled flags, parse TOML before/after, compare all semantic settings, check concurrent modifications, atomically replace and save backups beside the config; an external rename race preserves displaced contents and reports a conflict. A guarded undo restores only the last exact version. Export produces a sanitized diagnostic JSON without command lines, paths, credentials or document titles. Portable storage is explicitly limited to application output; config backup stays beside user config.

Tests cover parse/edit preservation and failures, unrelated process exclusion, duplicate attribution, missing/reused parents, disabled-but-running states and process identity safety. Native GUI rendering, seven in-process UI state checks and live read-only metrics are checked. Keyboard and hover behavior still need user interaction testing. Live Unity disabling is reserved for the user. Disposable TOML files and synthetic Codex/MCP process-tree fixtures validate the control logic without changing live integrations.

Local git repository prepared for later publication. Public GitHub creation and LinkedIn publication wait for user testing; document performance observations as a single workstation observation, not a universal savings claim or proven Codex bug.
